# Optional polkit password switch

This package does not enable `polkit-password-switch`. The option is an experimental, agent-specific protocol, not a polkit standard. Only enable it on a system where the sole polkit authentication agent handles this protocol. There is no capability negotiation: a stock agent will display the token if the option is enabled, including when an incompatible agent is used in another session. Leave the option out on systems with multiple or stock agents.

For an explicitly managed `/etc/pam.d/polkit-1`, add `polkit-password-switch` to its existing `pam_fprintd.so` auth line. Keep the rest of the PAM stack and its password fallback intact. Do not add it to other PAM services. A compatible agent must consume the `PAM_TEXT_INFO` message `fprintd:password-switch:<token>` and send an empty `UsePassword` signal on the system bus, interface `net.reactivated.Fprint.PasswordSwitch`, object path `/net/reactivated/Fprint/PasswordSwitch/<token>`, from the same process that opened the helper socket. The token is unique to the active scan. This naming is a proposal for this pilot, not an upstream agreement.

Before replacing the agent with an incompatible one, or downgrading or removing this package, remove the option from the polkit PAM line. The optional `aurora-omarchy-polkit` companion supplies an opt-in tool and a pre-transaction hook: the tool changes only a single existing fingerprint line and tracks the edit, and the hook removes it before either package is upgraded or removed. Normal package dependency checks also prevent downgrading fprintd below the compatible version while the companion is installed. The companion keeps aurora-sep’s ownership checksum in sync only for an unmodified managed PAM file; it preserves unrelated administrator edits and stops if its managed line has changed. See the companion README for activation and recovery instructions.

With the option absent, including the default configuration, stock agents receive no password-switch token. `test_password_switch.py` exercises this opt-out and checks that the active scan is stopped before the password prompt.
