# Aurora Omarchy password switch

This optional companion supplies the Omarchy dialog and the in-process Qt D-Bus bridge for fprintd-aurora's experimental password-switch protocol. The bridge uses the same process as the polkit agent, as required by the PAM module's sender check. It targets Omarchy's Quickshell plugin API; it is not a replacement for GNOME or KDE agents.

The companion advertises support on the system bus using a name bound to its PID. The PAM module checks that the name owner matches the helper socket peer before sending a token. Stock agents receive no token. Package installation alone does not change PAM or any user's shell configuration.

For the Omarchy user, copy `/usr/share/aurora-omarchy-polkit/plugin` to `~/.config/omarchy/plugins/aurora.polkit` and enable `aurora.polkit` through Omarchy's plugin manager. It replaces `omarchy.polkit` as its clone. Do not overwrite an existing user plugin. Confirm that the agent is active. Then run `pkexec /usr/bin/aurora-polkit-pam --enable`. This appends `polkit-password-switch` only to a single existing fingerprint auth line in `/etc/pam.d/polkit-1`; it does not create or change the rest of the password stack. If the file was managed by aurora-sep, its ownership checksum is kept in sync.

To turn it off, run `pkexec /usr/bin/aurora-polkit-pam --disable` before disabling or replacing the companion agent, then disable/remove the user plugin and restore the original agent. The tool restores the fingerprint line it changed and preserves unrelated edits. If that line has changed, the tool stops and requires manual resolution. It updates aurora-sep's checksum only if the file still matches aurora-sep's recorded checksum. Other edits are treated as administrator-owned.

The package depends on `fprintd-aurora>=1.94.5-5`, so normal pacman transactions refuse an incompatible downgrade while the companion remains installed. A pre-transaction hook also disables the PAM option before either package is upgraded or removed, including a forced fprintd downgrade. The option is disabled on every upgrade; after checking that the compatible agent is still active, re-enable it with `pkexec /usr/bin/aurora-polkit-pam --enable`. If the managed PAM line was edited, the hook warns and the transaction continues without changing that line. Remove `polkit-password-switch` manually before using an incompatible fprintd or agent; the recorded edit remains until it is resolved. The per-user plugin is not deleted automatically; with the option disabled it no longer offers the button and can be removed by its owner.
